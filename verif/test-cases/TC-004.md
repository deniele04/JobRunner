# TC-004

| Campo | Contenido |
|---|---|
| **Identificador** | TC-004 |
| **Requisitos cubiertos** | Criterio del Avance 1: «Consultar estado y listar trabajos». RF/RNF: por asignar (ver [matriz](../verification-plan/matriz-trazabilidad.md)) |
| **Objetivo** | Comprobar de extremo a extremo que el CLI consulta el estado de un trabajo y lista los trabajos del servicio, incluido el código de salida cuando el trabajo termina. |

## Precondiciones
1. Linux (Ubuntu 22.04 / 24.04) o WSL2 con Python 3.10 o superior.
2. Repositorio construido con `./scripts/setup.sh`.
3. Servidor y CLI integrados en la rama (`src/jobrunner/server.py` y `src/jobrunner/cli.py`).
4. Servicio en ejecución: `./scripts/run.sh` en una terminal (a mano). La automatización lo levanta sola, aislada, en un directorio temporal.

## Pasos
| # | Acción |
|---|---|
| 1 | En otra terminal, desde la raíz del repositorio: `export PATH="$PWD/scripts:$PATH"` (habilita `royito`). |
| 2 | Enviar un trabajo: `royito submit -- sleep 10`. Anotar el ID. |
| 3 | Consultar su estado de inmediato: `royito status <id>`. |
| 4 | Listar los trabajos: `royito list`. |
| 5 | Esperar a que termine el comando (más de 10 s) y repetir `status <id>`. |

## Resultado esperado
- Paso 3: el estado es `RUNNING`.
- Paso 4: la lista incluye el ID del paso 2 con su estado.
- Paso 5: el estado es `SUCCEEDED` y el código de salida es 0.

## Automatización
`verif/integration/test_tc004_consultar_listar.py`. Usa `sleep 2` en lugar de `sleep 10` para que dure segundos; el comportamiento comprobado es el mismo. Además verifica el filtro `list --state`, el error de un ID inexistente, el estado `FAILED` con su código y RNF-05 (`status` en menos de 1 s con 100 trabajos).

## Resultado observado
Ejecución `20261028-integracion`: 7 de las 8 pruebas pasan (RUNNING inmediato, el ID aparece en `list`, SUCCEEDED con código 0, FAILED con su código, filtro por estado, error por ID inexistente, `status` en menos de 1 s con 100 trabajos) y **1 falla**: `test_status_y_list_exitosos_terminan_con_codigo_0`. `status` de un trabajo existente termina con código de salida 1 aunque la consulta es correcta; `list` sí devuelve 0. Misma causa que **DEF-003** (ver TC-001 y la [matriz](../verification-plan/matriz-trazabilidad.md)).
