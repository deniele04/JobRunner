# TC-016

| Campo | Contenido |
|---|---|
| **Identificador** | TC-016 |
| **Requisitos cubiertos** | RF-25 (comportamiento ante saturación), RF-05 (cola). Decisión: [ADR-0004](../../docs/decisions/0004-cola-concurrencia-y-saturacion.md). |
| **Objetivo** | Comprobar que, con `--max-jobs` trabajos corriendo y la cola llena (`--queue-size`), el servicio rechaza de inmediato la solicitud nueva con un mensaje claro, registra el rechazo en la bitácora, no crea ningún trabajo y no afecta a los trabajos ya aceptados. |

## Precondiciones
1. Linux (Ubuntu 22.04 / 24.04) o WSL2 con Python 3.10 o superior.
2. Repositorio clonado. Las pruebas unitarias no requieren el servicio en ejecución ni dependencias externas.

## Pasos
| # | Acción |
|---|---|
| 1 | Desde la raíz del repositorio: `./scripts/setup.sh`. |
| 2 | Ejecutar la verificación: `verif/scripts/verify.sh <run-id>` (o `PYTHONPATH=src python3 -m unittest discover -s verif/unit -v`). |
| 3 | En `unittest.log`, comprobar el resultado de: `test_cola_llena_rechaza_y_no_registra_el_trabajo`, `test_el_rechazo_no_afecta_a_los_trabajos_aceptados`, `test_queue_size_cero_rechaza_al_llenarse_el_limite`, `test_submit_con_cola_llena_responde_error_y_no_crea_trabajo` y `test_el_servidor_sigue_respondiendo_despues_del_rechazo`. |
| 4 | Prueba manual: Servicio con `./scripts/run.sh --max-jobs 2 --queue-size 1` (en otra terminal se usa `royito`). Enviar cuatro veces `royito submit sleep 30` y después `royito list`. |

## Resultado esperado
- Con `max_jobs=1` y `queue_size=1`, el tercer `submit` lanza `ColaLlena` y no queda registrado (la lista sigue teniendo 2 trabajos).
- Por el socket, la respuesta es `{"error": "cola llena (capacidad N); intenta más tarde"}` y el CLI termina con código 1.
- El trabajo en ejecución y el de la cola conservan su estado; el servicio sigue respondiendo a `list` y `status`.
- La bitácora registra `ERROR rechazado job=- motivo="cola llena"`.
- Con `queue_size=0` se rechaza en cuanto se llena el límite de concurrencia.

## Resultado observado
Durante el desarrollo (29/10/2026, Linux, Python 3.12): las pruebas unitarias terminan en `PASS`. En la prueba manual con `--max-jobs 2 --queue-size 1`, el cuarto `submit` respondió `cola llena (capacidad 1); intenta más tarde`, `list` mostró 2 `RUNNING` y 1 `QUEUED`, y la bitácora registró `rechazado`. Falta la ejecución formal.
