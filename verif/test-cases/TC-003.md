# TC-003

| Campo | Contenido |
|---|---|
| **Identificador** | TC-003 |
| **Requisitos cubiertos** | Criterio del Avance 1: estados y transiciones del modelo (`QUEUED → RUNNING → SUCCEEDED \| FAILED \| CANCELED`). RF/RNF: por asignar (ver [matriz](../verification-plan/matriz-trazabilidad.md)) |
| **Objetivo** | Comprobar que un trabajo cambia de estado solo por transiciones válidas, que termina en `SUCCEEDED` o `FAILED` según su ejecución y que las transiciones inválidas se rechazan sin alterar el estado. |

## Precondiciones
1. Linux (Ubuntu 22.04 / 24.04) o WSL2 con Python 3.10 o superior.
2. Repositorio clonado. No se requiere el servicio en ejecución ni dependencias externas.

## Pasos
| # | Acción |
|---|---|
| 1 | Desde la raíz del repositorio: `./scripts/setup.sh`. |
| 2 | Ejecutar la verificación: `verif/scripts/verify.sh <run-id>` (o `PYTHONPATH=src python3 -m unittest discover -s verif/unit -v`). |
| 3 | En `unittest.log`, comprobar el resultado de: `test_exito_termina_en_succeeded_con_codigo_0`, `test_codigo_de_salida_distinto_de_cero_termina_en_failed`, `test_transiciones_validas` y `test_transiciones_invalidas_lanzan_error`. |

## Resultado esperado
- Un comando que termina con código 0 deja el trabajo en `SUCCEEDED`.
- Un comando que termina con código distinto de 0 lo deja en `FAILED`.
- `QUEUED → RUNNING → SUCCEEDED` es válida.
- Las transiciones `QUEUED → SUCCEEDED`, `QUEUED → FAILED`, `SUCCEEDED → RUNNING`, `FAILED → RUNNING` y `CANCELED → RUNNING` lanzan `ValueError` y el estado no cambia.

## Resultado observado
Ejecución `20261002-avance1` (Python 3.13.16, Linux): las cuatro pruebas terminan en `PASS`, incluidos los cinco casos de transición inválida.
