# TC-008

| Campo | Contenido |
|---|---|
| **Identificador** | TC-008 |
| **Requisitos cubiertos** | RNF-08 (una solicitud inválida o una desconexión de cliente no termina el servicio) y RNF-09 (la terminación anormal de un trabajo no afecta a otros). Título en el PDF 05: «Aislamiento de fallo». Criterio del Avance 1: «Manejo de comandos inválidos sin terminar el servicio» |
| **Objetivo** | Comprobar que un comando inexistente, una lista de argumentos vacía, una solicitud mal formada, bytes que no son texto o un cliente que se desconecta producen un error controlado o se ignoran, y que el servicio sigue aceptando trabajos. |

## Precondiciones
1. Linux (Ubuntu 22.04 / 24.04) o WSL2 con Python 3.10 o superior.
2. Repositorio clonado. No se requiere el servicio en ejecución ni dependencias externas.

## Pasos
| # | Acción |
|---|---|
| 1 | Desde la raíz del repositorio: `./scripts/setup.sh`. |
| 2 | Ejecutar la verificación: `verif/scripts/verify.sh <run-id>` (o `PYTHONPATH=src python3 -m unittest discover -s verif/unit -v`). |
| 3 | En `unittest.log`, comprobar el resultado de: `test_comando_inexistente_falla_sin_tumbar_el_gestor`, `test_argv_vacio_se_rechaza_y_no_registra_trabajo`, `test_solicitud_mal_formada_no_tumba_al_servicio`, `test_bytes_que_no_son_texto_valido` y `test_cliente_que_se_desconecta_antes_de_la_respuesta`. |

## Resultado esperado
- Un comando que no existe deja el trabajo en `FAILED`, sin código de salida, con el mensaje de error («No se pudo ejecutar…») y `finished_at` registrado.
- Un envío posterior (`true`) termina en `SUCCEEDED`: el gestor sigue operativo.
- Una lista de argumentos vacía lanza `ValueError` y no registra ningún trabajo.
- Una solicitud que no es JSON, bytes que no son texto válido o un cliente que se desconecta antes de la respuesta no terminan el servicio: el siguiente `submit` se atiende.
