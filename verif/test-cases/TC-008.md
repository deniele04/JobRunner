# TC-008

| Campo | Contenido |
|---|---|
| **Identificador** | TC-008 |
| **Requisitos cubiertos** | Criterio del Avance 1: «Manejo de comandos inválidos sin terminar el servicio». RF/RNF: por asignar (ver [matriz](../verification-plan/matriz-trazabilidad.md)) |
| **Objetivo** | Comprobar que enviar un comando inexistente o una lista de argumentos vacía produce un error controlado y que el gestor sigue aceptando trabajos. |

## Precondiciones
1. Linux (Ubuntu 22.04 / 24.04) o WSL2 con Python 3.10 o superior.
2. Repositorio clonado. No se requiere el servicio en ejecución ni dependencias externas.

## Pasos
| # | Acción |
|---|---|
| 1 | Desde la raíz del repositorio: `./scripts/setup.sh`. |
| 2 | Ejecutar la verificación: `verif/scripts/verify.sh <run-id>` (o `PYTHONPATH=src python3 -m unittest discover -s verif/unit -v`). |
| 3 | En `unittest.log`, comprobar el resultado de: `test_comando_inexistente_falla_sin_tumbar_el_gestor` y `test_argv_vacio_se_rechaza_y_no_registra_trabajo`. |

## Resultado esperado
- Un comando que no existe deja el trabajo en `FAILED`, sin código de salida, con el mensaje de error («No se pudo ejecutar…») y `finished_at` registrado.
- Un envío posterior (`true`) termina en `SUCCEEDED`: el gestor sigue operativo.
- Una lista de argumentos vacía lanza `ValueError` y no registra ningún trabajo.

## Resultado observado
Ejecución `20261002-avance1` (Python 3.13.16, Linux): las dos pruebas terminan en `PASS`.

Alcance: se verifica a nivel de `JobManager`. Cuando el servidor y el CLI estén integrados, hay que repetir el caso a nivel de servicio: el comando inválido debe devolver un error por el socket sin terminar el proceso del servicio.
