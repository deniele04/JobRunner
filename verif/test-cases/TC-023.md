# TC-023

| Campo | Contenido |
|---|---|
| **Identificador** | TC-023 |
| **Requisitos cubiertos** | RNF-32 (ver [matriz](../verification-plan/matriz-trazabilidad.md)) |
| **Objetivo** | Comprobar el campo de versión del protocolo (ADR-0009): toda respuesta lleva `v`, una solicitud sin `v` se toma como versión 1 y una versión distinta recibe un error claro sin ejecutar nada. |

## Precondiciones
1. Linux (Ubuntu 22.04 / 24.04) o WSL2 con Python 3.10 o superior.
2. Repositorio clonado. No se requiere el servicio en ejecución ni dependencias externas (las pruebas levantan su propio servidor en 127.0.0.1 con un puerto libre).

## Pasos
| # | Acción |
|---|---|
| 1 | Desde la raíz del repositorio: `./scripts/setup.sh`. |
| 2 | Ejecutar la verificación: `verif/scripts/verify.sh <run-id>` (o `./scripts/test.sh`). |
| 3 | En `unittest.log`, comprobar el resultado de las pruebas listadas abajo. |

Pasos manuales equivalentes: enviar `{"v": 2, "cmd": "list"}` al servicio; la respuesta es `{"v": 1, "error": "version de protocolo no soportada: 2 (soportada: 1)"}`.

## Resultado esperado
- Toda respuesta (éxito, error, JSON inválido, mensaje demasiado grande) lleva `"v": 1` como primer campo.
- Sin `v` la solicitud se atiende como versión 1; con `"v": 1` también.
- Una versión distinta (incluidos `"1"`, `1.0` y `true`) recibe el error exacto del ADR, no ejecuta nada, se registra y la conexión sigue viva.
- La versión se revisa antes que el comando.
- La CLI envía `v`, rechaza un servidor con otra versión y calcula su código de salida ignorando `v`; un trabajo FAILED sigue siendo exit 0.
