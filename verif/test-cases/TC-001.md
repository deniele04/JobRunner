# TC-001

| Campo | Contenido |
|---|---|
| **Identificador** | TC-001 |
| **Requisitos cubiertos** | Criterio del Avance 1: «Enviar un trabajo y obtener un ID único». RF/RNF: por asignar (ver [matriz](../verification-plan/matriz-trazabilidad.md)) |
| **Objetivo** | Comprobar de extremo a extremo que el CLI envía un trabajo al servicio por el socket Unix, recibe un ID y que dos envíos nunca reciben el mismo ID. |

## Precondiciones
1. Linux (Ubuntu 22.04 / 24.04) o WSL2 con Python 3.10 o superior.
2. Repositorio construido con `./scripts/setup.sh`.
3. Servidor y CLI integrados en la rama (`src/jobrunner/server.py` y `src/jobrunner/cli.py`).
4. Servicio en ejecución: `./scripts/run.sh` en una terminal.

## Pasos
| # | Acción |
|---|---|
| 1 | En otra terminal, desde la raíz del repositorio: `export PYTHONPATH=src`. |
| 2 | Enviar un trabajo: `python3 -m jobrunner.cli submit -- sleep 10`. Anotar el ID devuelto. |
| 3 | Enviar un segundo trabajo con el mismo comando y anotar su ID. |
| 4 | Consultar el primero: `python3 -m jobrunner.cli status <id>`. |

## Resultado esperado
- Cada `submit` devuelve un ID.
- Los dos IDs son distintos.
- `status <id>` reconoce el ID devuelto y muestra su estado.

## Resultado observado
**No ejecutado.** Ejecución `20261002-avance1`: no existe `src/jobrunner/cli.py` ni `src/jobrunner/server.py` en esta rama; ambos están en `feature/docs-server-cli`, sin integrar a `main`.

**Hallazgo complementario (nivel unitario, no forma parte de los pasos de este caso):** `verif/unit/test_ids_unicos.py` genera 2000 trabajos y **falla**: 33 IDs repetidos, porque cada ID tiene solo 4 caracteres hexadecimales (65 536 valores posibles). Registrado como **DEF-001** en la [matriz](../verification-plan/matriz-trazabilidad.md). Este caso no puede pasar a PASS mientras DEF-001 siga abierto.
